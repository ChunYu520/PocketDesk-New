## 2. PRD 验收标准映射

| 编号 | PRD 条件 | 实现方式 | 验证 |
| :--- | :--- | :--- | :--- |
| **AC-01** | 点击收纳盒背景/图标，浏览器不失焦、组件层不抢前台 | 默认 `WS_EX_NOACTIVATE`；`WM_MOUSEACTIVATE → MA_NOACTIVATE`；`ShowActivated=false` | 自动化：exstyle、`WM_MOUSEACTIVATE`、前台窗口不变 |
| **AC-02** | 点击卡片 A，卡片 B 的边框/高亮/阴影不变 | 卡片视觉只由 `CardViewModel` 驱动；自定义画刷；无 inactive 状态样式；输入指示线仅当前卡片可见 | 代码审查 + 双卡截图；自动化验证输入态只标记当前卡片 |
| **AC-03** | 点击搜索框出现强调色指示线并可输入；切到 B 后指示线移动，A 视觉高亮不变 | `GotFocus` → 临时移除 `NOACTIVATE` → `SetForegroundWindow` → 卡片 `IsInputActive=true`；Esc 交还前台 | 自动化：合成点击搜索框后前台切到宿主、Esc 后回到原前台 |
| **AC-04** | 组件层可见，但最大化/全屏应用完整盖住 | owner=Progman + `HWND_BOTTOM` 停靠桌面层；非 TOPMOST；`WS_EX_TOOLWINDOW` | 自动化：owner 校验 + z 序位于前台窗口之下 + 非置顶；Win+D 实拍 |
| **AC-05** | 鼠标落在卡片间透明区域时点击/框选作用于桌面 | `WM_NCHITTEST` 返回 `HTTRANSPARENT` | 自动化：卡片区域 `HTCLIENT`、卡片间/桌面空白 `HTTRANSPARENT` |
| **AC-06** | 宿主不改代码，注册新 `IWidget` 即显示卡片；设置界面渲染其 Schema | `WidgetRegistry.LoadPlugins` + 独立 ALC；Snapshot 通过 IPC 暴露 Schema；WinUI 动态表单 | 自动化：天气 DLL 被发现、Schema 5 字段、IPC 添加/移除实例、设置写回 |
| **AC-07** | 设置界面修改默认圆角后，组件层即时或下次启动生效 | WinUI 滑块 → `settings.update` → `AppSettingsService.Replace` → `Theme.Apply` + 所有卡片重绘 | 自动化：改为 24 后快照立即返回 24 |

## 3. 功能验收（手工）

在 Windows 11 ARM64 + 200% DPI 上实际运行：

1. **桌面层**：打开浏览器/终端并最大化，组件层被完整盖住；回到桌面（Win+D），卡片浮起但不抢焦点。
2. **窗口拖动/缩放**：拖动卡片标题栏到任意位置，松开后位置持久化；从四边/四角缩放不漂移、不跳动（1.0.1 修复点）。
3. **设置入口**：点击卡片标题栏齿轮、右键“打开设置”、托盘“打开设置”三条路径都能打开 WinUI 3 设置窗口。
4. **点击穿透**：在卡片之间拖动框选，桌面图标被框选，组件层不响应。
5. **双卡视觉**：并排放置“工作资料”和“灵感收藏”，点击 A 的背景，B 的边框/阴影/文字不变化；点击 A 的搜索框，仅 A 顶部出现青色指示线。
6. **输入与交还**：在搜索框输入，Esc 后前台回到之前的窗口；点击另一张卡片背景不会激活窗口。
7. **拖入**：从资源管理器拖 4 个文件到“工作资料”，卡片即时刷新，文件移动到 `Storage\<盒Id>`。
8. **跨盒拖拽**：把“工作资料”中的文件拖到另一个普通盒，文件移动且两个卡片即时刷新；拖拽过程中没有系统 OLE 窗口闪烁。
9. **拖出**：把收纳项拖到资源管理器窗口，触发系统 OLE 拖拽（复制/移动）。
10. **三种模式**：普通盒移动文件；映射盒保留源文件；目标盒显示绑定文件夹内容。
11. **设置**：打开设置，修改圆角/不透明度/主题；卡片即时变化，无需重启宿主；设置窗口使用 Mica + 自定义标题栏。
12. **组件扩展**：设置 → 组件出现“天气”卡片类型，添加后卡片层出现天气卡片；修改城市/单位/强调色，天气卡片内容即时更新。

## 4. 数据安全验收

- 关闭宿主（结束进程）后重新启动，未完成的文件移动由 journal 恢复；测试覆盖“源+目标同时存在”和“目标缺失”两条路径。
- 同名冲突选择“保留两者”会生成 `名称 (2).ext`，两个文件都可访问。
- 映射盒删除收纳盒不改变源文件。
- 普通盒删除收纳项会把文件还原到原始路径；原路径被占用时回退桌面并加 `(restored)`。
- 删除收纳盒时先还原文件，再删数据库行与存储目录。

## 5. 非功能指标实测

测试环境：Windows 11 ARM64、2560×1600 @ 200%、.NET 10、Debug 构建。

| 指标 | 实测 |
| :--- | :--- |
| 冷启动到窗口可见（4 张卡片 + 插件，含演示数据） | 约 2.5–3.7 s |
| 工作集 | 约 111 MB |
| 私有内存 | 约 38 MB |
| 输入激活 | 合成点击后立即激活，Esc 后前台恢复 |

说明：PRD 的 1.5s 启动目标在当前 Debug + 4 卡片 + 插件加载场景下未达到；主要成本是 Avalonia 首帧、插件程序集加载和卡片控件树构建。后续可通过 Release/ReadyToRun、延迟加载非首屏组件、图标按需加载优化。内存按私有内存口径约 38 MB；工作集包含共享 DLL 映射。
